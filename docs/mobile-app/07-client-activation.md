# 07 · تفعيل حساب العميل (§13)

سكة `AccountActivation` الخادمية نفسها — لا محرك تفعيل ثانٍ.

## التدفق

1. الدعوة (ويب أو جوال) تنشئ مستخدم `client` **بلا كلمة سر**، وتصدر رسالة
   فيها رابط `activate/{token}` ورمز 6 أرقام — لا كلمة سر في أي صادر أبداً.
2. التطبيق يلتقط الرابط (`/activate/{token}` — نقطة عامة تسبق الدخول):
   `GET activation/{token}` ⇒ `{status: pending|expired, email_masked}` —
   البريد مقنع قبل الإثبات، ورمز مجهول 404 بلا كشف وجود.
3. شاشة التفعيل: رمز + كلمة يضعها العميل (بتأكيدها) ⇒
   `POST activation/{token}/complete` — إتمام **ذري**:
   - كلمة ضعيفة ⇒ 422 **دون حرق الرمز** (يعاد الإدخال).
   - رمز خاطئ يرفع العداد، وسقف المحاولات يحرق الصف.
   - منتهي ⇒ 422 بـ`details.reason='expired'` — الشاشة تعرضه بصدق.
   - نجاح ⇒ حرق لمرة + ترقية العضويات `invited→active` +
     `{activated: true, email}` — **بلا جلسة**.
4. التوجيه لشاشة الدخول بالبريد الكامل معبأً وشارة نجاح — الدخول عبر
   `auth/login` الواحدة بكلمته التي وضعها بنفسه.

الكلمة لا تُسجل ولا تُخزن محلياً؛ الرموز لا تظهر في أي سجل (المسجل الحاجب).
