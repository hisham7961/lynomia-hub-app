# 03 · المصادقة والجلسة

السكة الواحدة `auth/login` لكلا الجمهورين (الداخلي والعميل) — لا سكة دخول ثانية.

- **زوج رمزين:** وصول قصير + تحديث متجدد لمرة، sha256 خادمياً، ويخزنان في
  Keychain/Keystore عبر `SecureStore` — لا يهبطان قرصاً غير مشفر ولا يُسجلان.
- **تدوير أحادي الرحلة:** `SessionManager` يضمن تجديداً واحداً متزامناً؛
  إعادة استعمال رمز مدور تبطل العائلة خادمياً وتعيد التطبيق للدخول.
- **MFA:** تحدي `challenge_id` + TOTP (السكة تعلن `totp` حصراً — لا يُختلق ما
  لا يُتحقق).
- **الحراس الخمسة** خادمية عند الدخول وعلى كل طلب (موقوف/مقفول/منتهٍ/IP/lockdown).
- **التصعيد (§7):** `runWithStepUp` يلتقط 428 `STEP_UP_REQUIRED` ويقرأ
  `details.purpose` المسمى، يطلب الاعتماد، ينادي `auth/step-up`، ويعيد
  العملية مرة واحدة — المنحة مربوطة بالغرض خادمياً ولا تتبادل.
- **البوابة البيومترية (§6):** قفل محلي اختياري فوق الجلسة — القوالب لا تغادر
  الجهاز أبداً ولا يستقبل الخادم بصمة.
- **تفعيل حساب العميل** لا يمس هذه السكة: الإتمام يعيد `{activated, email}`
  **بلا جلسة**، ثم يدخل العميل عبر `auth/login` نفسها (انظر `07-client-activation.md`).

التفصيل الكامل في `docs/authentication.md`.
