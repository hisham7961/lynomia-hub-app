# المصادقة والجلسة (§32–§41)

## التدفق

```text
POST auth/login {email, password, installation_uuid, platform,
                 app_version, app_build, device_model, os_version, locale, tz}
  ├─ 200 زوج رموز + user            → تبنٍّ ذري في SessionManager
  ├─ 401 MFA_REQUIRED {challenge_id, methods:["totp"], expires_at}
  │      → شاشة الرمز → POST auth/mfa/verify {challenge_id, code} → زوج
  └─ 401 UNAUTHENTICATED            → رسالة واحدة لا تميز (لا تعداد)
```

- **الوصول** قصير (~15 د) — في الذاكرة + المخزن الآمن لصحة الإقلاع البارد؛
  لا يُسجل ولا يُعرض ولا يوضع في رابط أو تحليلات (§34).
- **التحديث** متجدد لمرة — المخزن الآمن حصراً (§35).
- **تسلسل التحديث (§36):** `SessionManager.refreshNow` عملية واحدة مشتركة —
  تزامن 401 ينتظر التدوير نفسه (مثبت اختباراً: خمسة لا يرسلون خمسة).
- **التدوير (§37):** النجاح يستبدل الزوج ذرياً؛ `REFRESH_TOKEN_INVALID` يمسح
  ويعيد للمصادقة — لا إعادة للرمز القديم (خادمياً إعادة استعماله تبطل العائلة).
- **`SESSION_REVOKED` (§38):** إنهاء فوري + شرح للمستخدم.
- **الخروج (§39):** `logout`/`logout-all` خادمياً + مسح الرموز والسياق والخبيئة
  وإلغاء تسجيل الدفع؛ إدارة الجلسات في حسابي (قائمة/إبطال).
- **البيومترية (§40):** قفل محلي اختياري يفتح الوصول للجلسة المخزنة عبر
  `local_auth` بسقوط لاعتماد الجهاز — لا معطى حيوي يغادر الجهاز أبداً.
- **التصعيد (§41):** `STEP_UP_REQUIRED` (428 بـ`{purpose, method}`) ⇒ حوار
  اعتماد ⇒ `POST auth/step-up` ⇒ إعادة العملية مرة (`runWithStepUp`) — المنحة
  خادمية مربوطة بـ(الجلسة+الغرض+المهلة)، لا رفع دائم.

## معرف التنصيب (§29)

UUID عشوائي عند أول تشغيل في المخزن الآمن — لا IMEI ولا معرف إعلانات.

## بوابة الإقلاع (§28 §45 §46)

`LaunchController`: بيئة ← app-config (صيانة/قفل/بوابة إصدار) ← جلسة مخزنة ←
قفل بيومتري ← bootstrap ← جاهز. تحديث إلزامي = `update_required && force_update`
⇒ شاشة حاجبة بزر متجر حقيقي أو رسالة NOT_CONFIGURED صادقة.
