# المزامنة دون اتصال (§60–§66)

## القرار المعماري للتشفير (§63)

بدل قاعدة SQLCipher أصلية (سلاسل توافق toolchain عبر iOS/Android)، الخبيئة
لقطات JSON مشفرة **AES-256-GCM** ملفاً لكل نطاق (nonce عشوائي لكل كتابة + وسم)،
والمفتاح 32 بايت في Keychain/Keystore ولا يغادره. النتيجة نفسها: لا قاعدة
مؤسسية نصية على القرص (مثبت اختباراً: البايتات لا تحوي النص الصريح). لو نمت
الحاجة لاستعلامات محلية معقدة، الترقية إلى SQLCipher قرار لاحق موثق —
لا تنازل أمني صامت.

## أصناف الخادم تطاع (§61)

| الصنف | سلوك التطبيق |
|---|---|
| `CACHEABLE_INCREMENTAL` (81 وحدة) | خبئ، زامن بالمؤشر، طبق tombstones، احمل `version` لكل سجل وابعثه `If-Match` |
| `CACHEABLE_READ_ONLY` | خبئ للقراءة بلا رمز تعارض |
| `ONLINE_ONLY` (الافتراض) | لا تخبئة — ويرفضها `EncryptedJsonCache` بنيوياً |
| `SENSITIVE_NO_PERSIST` (`phones`/`carriers`/`vault`) | **لا قرص إطلاقاً** — الخادم لا يبث سجلاً أصلاً، والمحرك يمحو أي بقايا، والكتابة ترمي `CachePolicyViolation` (§62 §111) |
| `NOT_APPLICABLE` (`users`) | من `context`/`bootstrap` |

## المؤشرات والعزل (§64)

مفتاح الحالة: `sync_u_{user}_c_{company|-}_k_{client|-}_{module}` — مؤشر شركة
لا يخدم أخرى بنيوياً (مثبت اختباراً)، وتبديل السياق/الخروج يمسح بالبادئة.
تخزن: المؤشر المعتم، `sync_version`، السجلات بنسخها، حالة الشواهد.

## الدورة

1. `GET sync/{module}?cursor=` حتى `has_more=false`.
2. `tombstones` تحذف من الخبيئة (§65)؛ `has_tombstones=false` ⇒ الغياب إسقاط.
3. تغير `sync_version` ⇒ تصفير وإعادة كاملة.
4. حقل `sec` مجرد خادمياً — لا يصل أصلاً.

## الكتابة دون اتصال (§66)

لا طابور كتابة offline عام: العقد الحالي لا يعلن أمان التصفيف لكل عملية،
فالكتابة تتطلب اتصالاً وتقول ذلك بصدق (`يتطلب اتصالاً بالإنترنت`). إعادة
محاولة عملية مقدمة فعلاً تبقى آمنة عبر `Idempotency-Key` الثابت (§58) —
وهذا مختلف عن إنشاء حر دون اتصال.

## الحالات (§83 §84)

قائمة الوحدة عند الانقطاع تسقط للخبيئة بلافتة «نسخة مخبأة» وزر إعادة؛ شريط
«لا اتصال» هادئ في الغلاف؛ لا نوافذ إزعاج.
